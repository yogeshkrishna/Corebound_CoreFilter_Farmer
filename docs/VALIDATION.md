The lint warnings are eight English text-construction warnings, plus one each for an API-dependent attribute, fixed calibration orientation, ARM64-only Chrome OS support, backup configuration across API levels, and the draggable status label's accessibility click handling. They are retained as visible warnings, not hidden in a baseline. English phone support and the fixed landscape calibration view are deliberate support limits.

The suite covers screen confirmation and transition retries; the result → Continue → world selection → PLAY → loading → gameplay cycle; ad timeout/manual resolution; stale/duplicate frames and OCR; input acknowledgments; session/loading/unknown deadlines; foreground/orientation guards; jump/recovery budgets; correlation and camera movement; configuration corruption and bounded reads; incomplete atomic writes and missing-primary backup recovery; diagnostic URI restrictions; finite simultaneous touches; cancellation, watchdogs and executor cleanup. Calibration tests drive the actual screen with letterboxed touch coordinates, save all five points, check exact extracted templates, exercise Undo/Cancel, and reject flat/edge patches without replacing the existing profile.

**Host-filesystem boundary:** Robolectric executes framework file operations on Windows. Android's rename-over-existing behavior differs from Windows `File.renameTo`. Calibration fixture replacement explicitly removes the prior fixture, and backup recovery tests use a missing primary. This does not validate replacement durability on a real Android filesystem; that remains part of the device trial.

## Recorded input and performance

Four sequential frames from the supplied `video-01.mp4` recording, indices **516, 528, 540 and 552**, are replayed at 640 × 295. Tests confirm tracking of the calibrated Crawler and nearby floor probes, with no false close walls/ceilings in those tested views. These four views do not establish complete map coverage, robustness for all hulls, or menu recognition on a phone.

The final 40-iteration JVM replay benchmark returned **40 valid detections**, median **43.818 ms**, p95 **55.241 ms**, maximum **56.112 ms**, measured during the build. This measures desktop image processing, not Android screenshot/OCR latency, phone FPS, kills/hour, or filters/hour. There is no measured phone comparison or claimed farming speedup.

The implementation limits OCR to one in-flight task and at most one start per second, reuses image buffers, adapts capture cadence to measured vision CPU time, bounds retry histories, and does no polling while paused or stopped. Capture, gesture and OCR watchdogs prevent automatic unbounded retries; an unresponsive OCR SDK requires accessibility-service recreation if it never returns.

## Reproduce

From the project directory, use the documented PowerShell build helper, or run the complete checked task set with JDK 17 and Android SDK 35 configured:

```text
gradlew.bat :engine:test :engine:benchmark :app:testDebugUnitTest :app:lintDebug :app:lintRelease :app:assembleDebug :app:assembleRelease
```

`tools/format.ps1 -Check` verifies formatting. `tools/sign.ps1` signs with a distributor-owned key and checks the resulting signature and alignment. `tools/package.py --apk <signed-apk>` creates the source archive and checksums. The included GitHub workflow has not been executed on a hosted runner.

The release APK is **14,041,324 bytes**. Its SHA-256 is:


## Remaining real-world gate

`adb devices -l` returned no connected device, and no emulator/system image was available. **No live Core Filter farming, reward pickup, inventory increase, sustainable farming rate, or full procedural-cave coverage was verified.** No account or game save was accessed. OCR and platform screenshot/gesture behavior were not exercised against a running Corebound instance.

Before calling this production-proven, install on an ARM64 Android 11+ phone with the audited **Corebound 1.2.1.1 / build 140**, calibrate on that phone, and supervise a complete run and restart. Verify movement/jump edges, interrupted-screen recovery, actual result/world screens, optional ad handling, prolonged patrol and an inventory increase following a real pickup. Record initial/final inventory independently; the app's filter-label counter is not pickup evidence. Unknown UI or insufficient terrain recognition should pause, allowing manual resolution and resume.
